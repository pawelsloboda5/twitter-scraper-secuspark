## Directory Purposes

**src/:**
- Purpose: TypeScript source code for the scraper library
- Contains: Feature modules, auth, API request handling, timeline parsing, data types
- Key files: scraper.ts (main class), _module.ts (export entry), auth.ts/auth-user.ts (authentication)

**src/platform/:**
- Purpose: Runtime environment abstraction
- Contains: Platform interface, Node.js-specific cipher randomization
- Build constant PLATFORM_NODE determines which impl is loaded

**dist/:**
- Purpose: Compiled JavaScript and type definitions for distribution
- Generated: Rollup build creates 4 separate builds:
  - default/* (browser/generic, PLATFORM_NODE=false)
  - node/* (Node.js optimized, PLATFORM_NODE=true, inlined dynamic imports)
  - cycletls/* (Node.js with external cycletls dependency)
  - types/* (TypeScript declarations for all variants)

**examples/:**
- Purpose: Reference implementations showing library usage
- Contains: Separate projects for different runtimes (Node, React, proxy, etc.)
- Each has own package.json and tsconfig.json

## Naming Conventions

**Files:**
- Feature modules: kebab-case, clear intent (tweets.ts, search.ts, auth-user.ts)
- Timeline parsers: timeline-{variant}.ts (timeline-v1.ts, timeline-search.ts, timeline-async.ts)
- Utilities: utility-specific (requests.ts, errors.ts, type-util.ts)
- Test files: {name}.test.ts (collocated with implementation)
- Entry points: underscore prefix (_module.ts, _cycletls.ts)

**Directories:**
- Feature directories: kebab-case (src/platform/node/)
- Source directory: src (convention, excluded from dist)
- Build outputs: platform/variant structure (dist/node/cjs/, dist/default/esm/)

**Exports:**
- Main: Named exports (export interface, export type, export class, export function)
- Barrel files: None; individual files imported directly
- Internal: Avoid "internal" convention; use underscore prefix for build entries

## Where to Add New Code

**New Feature (e.g., Spaces API):**
- Primary code: `src/spaces.ts` (data types + fetch functions)
- Timeline parsing: `src/timeline-spaces.ts` (if needed)
- Tests: `src/spaces.test.ts`
- Integration: Add exported functions/types to `src/_module.ts`
- Scraper method: Add to Scraper class in `src/scraper.ts`

**New Timeline Parser (e.g., API v3 support):**
- Implementation: `src/timeline-v3.ts` (follow v2.ts structure)
- Types: Define response shape interfaces + ParseTimelineV3Result
- Export parse function: parseTimelineV3Tweets, parseTimelineV3Users
- Usage: Import in feature modules (tweets.ts, search.ts)

**Utilities & Helpers:**
- Shared parsing logic: `src/timeline-tweet-util.ts` (or new timeline-*-util.ts)
- Type utilities: `src/type-util.ts`
- Header/security generation: Alongside related auth file (xctxid.ts style)
- Cookie/request handling: `src/requests.ts`

**Auth Enhancements:**
- New auth type: Extend TwitterAuth interface and create new class (like TwitterUserAuth)
- Subtask handlers: Register via scraper.registerAuthSubtaskHandler()
- Platform-specific: Add to `src/platform/node/index.ts` or new platform variant
